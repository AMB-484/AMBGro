# Releasing AMBGro to Google Play

This app builds a signed **Android App Bundle (`.aab`)** for the Play Store.

> ⚠️ **The `/android` folder is git-ignored** (regenerated by CI / `npx cap add android`).
> The `android/app/build.gradle` signing snippet below is therefore NOT in git —
> if you ever regenerate `/android`, re-apply it from the "Gradle snippet" section.
> Your **keystore and passwords live in the project root**, outside `/android`, so a
> regeneration never destroys them.

---

## One-time setup

### 1. Generate the upload keystore (run once, in the project root)

Run this in `E:\DrAwais_GrowthApp`. It creates `ambgro-upload.jks` and prompts you
for a keystore password, a key password (press Enter to reuse the same one), and
your name/org details.

```bash
keytool -genkeypair -v -keystore ambgro-upload.jks -alias ambgro-upload -keyalg RSA -keysize 2048 -validity 10000
```

If `keytool` isn't found on PATH, use the one bundled with Android Studio:

```
"C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v -keystore ambgro-upload.jks -alias ambgro-upload -keyalg RSA -keysize 2048 -validity 10000
```

> 🔐 **Back up `ambgro-upload.jks` and both passwords** somewhere permanent (password
> manager + offline copy). With Google Play App Signing an upload key can be reset if
> lost, but treat it as irreplaceable. **Never commit it** (already git-ignored).

### 2. Create `keystore.properties` in the project root

Create `E:\DrAwais_GrowthApp\keystore.properties` with your real values:

```properties
storeFile=ambgro-upload.jks
storePassword=YOUR_KEYSTORE_PASSWORD
keyPassword=YOUR_KEY_PASSWORD
keyAlias=ambgro-upload
```

(Both `keystore.properties` and `*.jks` are git-ignored.)

## Build the release AAB (every release)

From the project root:

```bash
npm run build && npx cap sync android
```

Then build the bundle:

```bash
cd android && ./gradlew bundleRelease
```

Output: **`android/app/build/outputs/bundle/release/app-release.aab`** — this is the
file you upload to the Play Console.

To sanity-check that it was signed with your upload key:

```bash
cd android && ./gradlew signingReport
```

(Android Studio equivalent: **Build ▸ Build Bundle(s) / APK(s) ▸ Build Bundle(s)**.
Because signing is wired into Gradle, the resulting bundle is already signed.)

---

## Version bumps

Each Play upload needs a higher `versionCode`. In `android/app/build.gradle`:

```gradle
versionCode 1       // integer, must increase every upload: 1, 2, 3, ...
versionName "1.0"   // human-facing string shown in the store
```

## Notes

- `minifyEnabled` is **false** for release, matching what's been tested on-device
  (this app is a Capacitor WebView; R8/ProGuard stripping has caused subtle WebView
  bugs before). Enable it later only after verifying the release build on a device.
- Debug builds are unaffected by the signing config — it only applies when
  `keystore.properties` exists.

## Gradle snippet (re-apply if `/android` is regenerated)

Top of `android/app/build.gradle`, after `apply plugin: 'com.android.application'`:

```gradle
def keystorePropertiesFile = new File(rootProject.projectDir, "../keystore.properties")
def keystoreProperties = new Properties()
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}
```

Inside `android { ... }`, add a `signingConfigs` block and reference it from
`buildTypes.release`:

```gradle
signingConfigs {
    release {
        if (keystorePropertiesFile.exists()) {
            storeFile new File(rootProject.projectDir, "../" + keystoreProperties['storeFile'])
            storePassword keystoreProperties['storePassword']
            keyAlias keystoreProperties['keyAlias']
            keyPassword keystoreProperties['keyPassword']
        }
    }
}
buildTypes {
    release {
        if (keystorePropertiesFile.exists()) {
            signingConfig signingConfigs.release
        }
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
    }
}
```
